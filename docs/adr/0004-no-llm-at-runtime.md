# ADR-0004: LLM только на этапе разработки, рантайм детерминированный

## Status

Accepted (2026-09-03, Фаза 0)

## Context

Разбор новой формы — задача, где LLM объективно полезна: понять, какая
подпись относится к какому полю, в документе на сербском или немецком,
быстрее с моделью, чем вручную.

Соблазн — вызывать модель прямо из приложения: тогда каталог форм не
нужен, любая форма разбирается «на лету».

Но это означало бы отправку содержимого официальной формы, а вместе с
данными для заполнения — и паспортных данных пользователя — на сторонний
сервис.

## Decision

LLM используется **только на этапе разработки**: разработчик разбирает
новую форму оффлайн-утилитой (можно с помощью модели) и получает JSON-
шаблон, который проходит ревью и попадает в бандл приложения.

В рантайме у пользователя — только детерминированный локальный парсер.
Никаких обращений к AI или сети.

## Consequences

### Positive

- Паспортные данные не покидают устройство — согласуется с ADR-0002.
- Заполнение работает офлайн и всегда одинаково: один вход → один выход,
  ошибку можно воспроизвести и починить.
- Нет стоимости за вызов модели, нет её латентности в UX.
- Нет риска галлюцинации в номере документа. На критичных полях
  недетерминированность неприемлема: ошибка в номере паспорта — это
  отклонённое заявление и упущенный срок подачи.
- Шаблон проходит ревью человеком один раз, а не «доверяемся модели»
  каждый раз у каждого пользователя.

### Negative

- Новая форма не работает, пока разработчик её не разберёт и не выпустит
  обновление.
- Каталог не покрывает «длинный хвост» редких форм.

### Neutral

- Оффлайн-утилита разбора — часть инструментария репозитория, не продукта;
  её зависимости не попадают в бандл приложения.
- Решение не запрещает LLM навсегда: если когда-нибудь появится модель,
  работающая локально на устройстве, вопрос можно пересмотреть новым ADR —
  ограничение здесь в отправке данных наружу и в недетерминированности, а
  не в самой технологии.

## Alternatives Considered

**Вызов облачной LLM из приложения**
- Отвергнуто: отправка паспортных данных третьей стороне, требование сети,
  стоимость, недетерминированность на критичных полях.
- В плюс шло: покрытие любой формы без каталога.

**Локальная модель на устройстве**
- Отвергнуто на текущем этапе: размер бандла и требования к железу
  несоразмерны задаче, которая решается детерминированным парсером.

**Отправка только структуры формы, без данных пользователя**
- Отвергнуто: снимает часть риска, но оставляет требование сети и
  недетерминированность; выигрыш не оправдывает потери офлайна.
