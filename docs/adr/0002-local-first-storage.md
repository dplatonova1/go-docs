# ADR-0002: Local-first хранилище, без серверной части

## Status

Accepted (2026-09-03, Фаза 0)

## Context

Приложение обрабатывает сканы паспортов, свидетельств, банковских выписок и
сами паспортные данные. Для пользователя из ЕС это специальная категория ПД
под GDPR; для пользователя вне ЕС риск не меньше — утечка такого набора
означает готовый комплект для кражи личности.

Любой сервер, куда эти файлы попадут, становится и точкой отказа, и
объектом регулирования: нужны privacy policy, договор обработки, процедура
удаления, реакция на инциденты. Продукт при этом однопользовательский — по
своей природе он не требует ни совместного доступа, ни серверных
вычислений.

## Decision

Данные хранятся только на устройстве:

- метаданные (заявки, пункты чек-листа, документы) — SQLite через
  `op-sqlite`, миграции нумерованные;
- **база данных шифруется целиком** (SQLCipher, включается в
  `op-sqlite.sqlcipher` в package.json) тем же ключом, что и файлы:
  перечень заявок — «ВНЖ Сербия», список приложенных документов, даты —
  сам по себе рассказывает о человеке достаточно, чтобы не оставлять его
  открытым текстом в песочнице;
- сами файлы — на диске в зашифрованном виде, ключ в
  Keychain / Android Keystore через `react-native-keychain`;
- ключ не попадает в БД, логи и аналитику и не покидает устройство.

Разрешение `INTERNET` не объявляется в release-манифесте Android — только
в dev-вариантах, где оно нужно Metro. Отсутствие сетевого разрешения
пользователь может проверить сам в карточке приложения в сторе.

Облачная синхронизация — не раньше Фазы 6, только с client-side (E2E)
шифрованием и отдельным ADR.

## Consequences

### Positive

- Утечки на стороне сервиса невозможны: сервиса нет.
- Нет обязательств по обработке ПД на нашей стороне — до появления облака.
- Приложение полностью работает офлайн, в том числе в консульстве без сети.
- Нулевая стоимость инфраструктуры, а значит и монетизация не обязана
  покрывать хостинг.

### Negative

- **Единственная копия данных.** Потеря или сброс устройства = потеря
  собранного пакета. Резервного копирования нет.
- Нет синхронизации между устройствами пользователя.
- Нет серверной аналитики и crash-репортинга — диагностика проблем только
  по обращениям пользователей.
- Восстановление доступа невозможно: ключ в Keystore, «забыли пароль» не
  бывает.
- **Шифрование БД усиливает последствия потери ключа.** Если бы база была
  открытой, при сбое ключа ([ADR-0008](./0008-known-risk-keychain-decryption-failures.md))
  приложение могло бы хотя бы показать «вот ваши 12 документов, открыть
  их не получится» — человек понял бы, что у него было собрано. С
  зашифрованной базой недоступно всё, включая перечень. Компромисс принят
  сознательно: приватность метаданных сочтена важнее, чем возможность
  показать оглавление в аварийном сценарии.

### Neutral

- `android:allowBackup="false"` — автобэкап Google отключён осознанно,
  иначе зашифрованные файлы уехали бы в Google Drive пользователя.
- Риск потери данных нужно проговорить в UI явно, а не прятать в
  пользовательском соглашении; экспорт готового пакета наружу служит
  ручным бэкапом.

## Alternatives Considered

**Бэкенд с шифрованием at rest на сервере**
- Отвергнуто: ключи у нас — значит доступ к данным у нас, со всеми
  обязательствами и рисками. Для этого продукта серверные функции не нужны.
- В плюс шло: бэкап, синхронизация, аналитика.

**Хранение в открытом виде в песочнице приложения**
- Отвергнуто: на Android с root и через ADB-бэкап содержимое песочницы
  достаётся; для сканов паспорта этого недостаточно.
- В плюс шло: проще, быстрее, меньше кода.

**E2E-синхронизация сразу, с первой версии**
- Отвергнуто: не блокирует основной сценарий, но заметно усложняет Фазу 1
  (обмен ключами, разрешение конфликтов, восстановление). Перенесено в
  Фазу 6.
