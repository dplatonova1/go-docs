# ADR-0017: Библиотека документов — экран, прикрепление из неё, удаление файла

## Status

Accepted (2026-09-20, подготовка к Фазе 2)

Закрывает «Deferred» из
[ADR-0010](./0010-shared-document-library.md),
[ADR-0013](./0013-detach-deletes-document-in-phase-1.md) и
[ADR-0016](./0016-application-deletion-keeps-documents.md): экран, ради
которого снимались их инварианты, наконец существует.

## Обновление (2026-10-02, редизайн): миниатюры

**Превью — по миниатюре, сделанной один раз, а не по исходному файлу.**
Это меняет пункт 6 раздела Decision.

- При прикреплении снимка (JPEG, PNG) из уже расшифрованных байтов
  делается миниатюра: короткая сторона 160 px, JPEG 75, несколько
  килобайт. Тем же способом, что сжатие снимка для пакета, —
  `react-native-nitro-image` из буфера в памяти, без расшифрованной
  копии на диске (`src/features/library/thumbnail.ts`).
- **Миниатюра хранится в строке документа** — колонка
  `documents.thumbnail BLOB`, миграция 4. Не файлом рядом с документом:
  база зашифрована SQLCipher, так что миниатюра защищена тем же ключом;
  она удаляется вместе со строкой (удаление из библиотеки, каскады) — ни
  второго файла, ни его «сирот» при прерванной записи
  ([ADR-0012](./0012-delete-orphan-documents-with-application.md),
  раздел 4). Это единственное исключение из правила «в базе только
  метаданные» (`src/db/README.md`).
- Показ превью — чтение нескольких килобайт из базы. Ограничение «до 2
  МБ» снято: миниатюра есть у снимка любого допустимого размера.
- **У записей старше миграции 4** миниатюры нет: посчитать её в
  миграции нельзя — файлы зашифрованы, ключ в Keychain. Она делается при
  первом показе (один раз расшифровывается исходный файл, до предела
  прикрепления) и сразу сохраняется. Одновременные плитки одного
  документа делят одну загрузку.
- Сбой разбора картинки — не ошибка прикрепления: документ
  прикрепляется без миниатюры, в плитке заглушка.
- PDF по-прежнему без превью: нет нативного рендерера страниц.
- Превью теперь показывают и пункты чек-листа (карточка с картинкой):
  без миниатюр это была бы полная расшифровка каждого видимого файла.

Не сделано вместе с миниатюрами, хотя в CLAUDE.md записано «тем же
проходом»: **детектор качества при прикреплении** (`documents.quality_flag`
и пометка в чек-листе и библиотеке) — отдельный шаг.

## Context

Документы с самого начала спроектированы как общая библиотека
пользователя (ADR-0010), но показывались только внутри пунктов
чек-листа. Дальше два решения подряд перестали удалять файлы:
открепление стало снимать только связь (ADR-0013, «Обновление»), а
удаление заявки — не трогать документы вовсе (ADR-0016).

Результат: документ, не прикреплённый ни к одному пункту, существовал в
базе и на диске, но не был виден нигде, и удалить его было нельзя ничем,
кроме удаления приложения целиком. Для хранилища паспортных сканов это
хуже, чем неудобство: зашифрованные персональные данные копились без
выхода, что прямо противоречит границам доверия из
`docs/architecture.md`.

Вторая нерешённая вещь — переиспользование. Один и тот же скан паспорта
приходится прикреплять в каждой новой заявке заново: выбрать файл в
системном пикере, скопировать, зашифровать, записать. Ради того, чтобы
этого не делать, связь `checklist_item_documents` и сделана
many-to-many.

## Decision

1. **Экран библиотеки показывает всю таблицу `documents`** — имя, дату
   добавления и превью для изображений, новые сверху. Включая документы
   без единой связи: именно они были невидимы.

2. **Один экран в двух режимах.** Без пункта — просмотр библиотеки
   (доступно удаление). С пунктом (`PickDocumentFromLibrary`) — выбор
   файла для этого пункта (доступно прикрепление). Удаление в режиме
   выбора недоступно: необратимому действию не место рядом с обычным
   выбором файла.

3. **Прикрепление из библиотеки создаёт только связь.** Файл не
   читается, не копируется и не шифруется заново; в
   `checklist_item_documents` добавляется строка, пункт отмечается
   прикреплённым. Документ, уже прикреплённый к этому пункту, показан с
   отметкой и кнопкой в недоступном состоянии; повторная попытка
   (гонка) возвращает `already-attached` значением, а не исключением.

4. **«Удалить из библиотеки» — отдельное действие с другим смыслом, чем
   «открепить».** Открепление снимает одну связь и файл не трогает;
   удаление из библиотеки стирает файл с устройства и каскадом снимает
   документ со всех пунктов всех заявок. Разные слова, разные кнопки,
   разные экраны.

5. **Подтверждение перечисляет заявки поимённо**: «прикреплён к пунктам
   чек-листа (3) в заявках: «ВНЖ Сербия» — пунктов: 2; «ПМЖ» — пунктов:
   1». Счёт идёт по `checklist_item_documents` перед каждым удалением, а
   не берётся из списка: между открытием экрана и нажатием документ
   могли прикрепить ещё куда-то. Пункты, оставшиеся без файлов, внутри
   той же транзакции возвращаются в «не прикреплено».

6. **Превью — только JPEG и PNG размером до 2 МБ.** _Изменено
   2026-10-02: превью по миниатюре, см. «Обновление»._ Файлы зашифрованы,
   поэтому картинка читается, расшифровывается и отдаётся `Image` как
   `data:`-URI; строка делает это сама и только пока видна на экране.

## Consequences

### Positive

- Документы без связей видны и удаляемы — накопления зашифрованных
  данных без выхода больше нет.
- Скан, загруженный один раз, прикрепляется в следующую заявку одним
  нажатием, без системного пикера и без второй копии на диске.
- Удаление файла стало единственным местом, где файл действительно
  исчезает, и оно всегда показывает последствия.

### Negative

- **Превью расшифровывает файл целиком в памяти.** Отсюда ограничение в
  2 МБ и заглушка для всего остального: настоящие миниатюры (уменьшенная
  копия, сделанная один раз при прикреплении) — отдельная работа,
  записанная в «Отложенные обязательства».
- PDF в списке без превью, хотя именно PDF чаще всего и прикрепляют:
  рендер страницы требует нативного модуля.
- У документов нет пользовательского названия — в списке видно имя файла
  из источника, а оно бывает вида `IMG_0042.jpg`. Колонка
  `documents.display_name` по-прежнему в планах.

### Neutral

- Схема не меняется: все запросы ложатся на существующие индексы
  (`idx_cid_document_id` для «где используется», первичные ключи для
  остального). Список библиотеки — полный проход по `documents` с
  сортировкой во временном B-tree; документов сотни, индекс под эту
  сортировку не окупается.
- UI библиотеки живёт в `src/features/library`, запросы — в
  `features/checklist/repository.ts`: заводить второй слой доступа к тем
  же таблицам ради красоты границ было бы хуже.

## Deferred

- **Миниатюры при прикреплении** вместо расшифровки полного файла в
  списке; тогда же — превью первой страницы PDF, если найдётся способ без
  тяжёлой нативной зависимости.
- **`documents.display_name`** — пользовательское название документа
  («Паспорт, страница 1») новой миграцией.
- **Открытие документа на весь экран** из библиотеки: сейчас файл можно
  только прикрепить или удалить, но не посмотреть.

## Alternatives Considered

**Показывать в библиотеке только документы без связей**

- Отвергнуто: это экран «мусора», а не библиотеки. Переиспользование —
  главный сценарий, а оно требует видеть все документы.

**Прикреплять из библиотеки копией файла**

- Отвергнуто: вторая копия тех же байтов на устройстве и два документа,
  которые пользователь считает одним. Ровно та проблема, против которой
  принимался ADR-0010.

**Удаление из библиотеки без списка заявок, просто «файл используется в
3 пунктах»**

- Отвергнуто: числа не дают проверить, та ли это заявка. Список
  названий — единственное, что позволяет заметить ошибку до
  подтверждения.
