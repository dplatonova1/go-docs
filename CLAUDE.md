# Проект: чек-лист документов + автозаполнение форм для виз/ВНЖ/ПМЖ

## Описание

Мобильное приложение (React Native, bare, TypeScript). Пользователь вставляет
список требуемых документов (скопированный с официального сайта) →
приложение строит чек-лист → пользователь загружает файлы к каждому пункту →
приложение собирает финальный PDF-пакет для печати с реестром.
Отдельно: автозаполнение официальных форм (docx/PDF) данными из уже
загруженных документов (паспорт и т.п.), премиум-фича.

## Ключевые архитектурные решения

- **Хранение:** локально на устройстве по умолчанию (SQLite + зашифрованные
  файлы, ключ в Keychain/Keystore). Облачная синхронизация — опционально,
  позже, только с client-side (E2E) шифрованием.
- **Чек-лист:** текст от пользователя разбивается на пункты простой
  эвристикой (без ML/NLP).
- **Docx-парсинг форм:** legacy form fields (`w:ffData`/`FORMTEXT`), не
  content controls. Поля сопоставляются с данными **по позиции в документе +
  тексту подписи перед полем**, НЕ по имени bookmark'а — реальные формы
  переиспользуют одно имя (`Text12` и т.п.) на разных полях. Одно поле может
  соответствовать нескольким значениям сразу (например, номер паспорта +
  даты) — тогда заполняется одной строкой или оставляется вручную.
- **PDF-формы (AcroForm):** второй пайплайн на `pdf-lib`, общий интерфейс с
  docx-парсером. Нужен минимум для Шенгенской визы (официально PDF,
  регламентировано Visa Code Annex I; часть консульств — только веб-портал,
  без скачиваемого файла вообще).
- **Каталог форм:** маппинг полей строится один раз разработчиком (можно с
  помощью LLM) и хранится как статичный JSON-шаблон на форму. В рантайме —
  только детерминированный локальный парсер, без обращения к AI/сети.
  Загруженный файл сопоставляется с шаблоном по структурному fingerprint
  (не по имени файла). Каталог версионируется — на случай, если ведомство
  обновит форму.
- **AI/LLM используется только на этапе разработки** (разбор новой формы),
  не в рантайме у пользователя — по приватности, офлайн-работе, стоимости и
  точности на критичных данных (номера документов).
- **Паспортные данные:** MRZ-сканирование (не общий OCR) через
  `react-native-vision-camera` + MLKit-плагин, с обязательным ручным
  подтверждением каждого автозаполненного поля. Точность тестировать
  отдельно на iOS и Android.
- **Финальный экран:** формулировка "отмечено N из N пунктов чек-листа",
  не "всё готово" — во избежание ложной уверенности пользователя.
- **Стек:** `op-sqlite`, `react-native-keychain`, `@dr.pogodin/react-native-fs`,
  `react-native-vision-camera`, `pdf-lib`.
- **Юридическое:** перед платным тарифом — проверить регулирование
  "иммиграционного консультирования" в целевых юрисдикциях; для облачной
  синхронизации — privacy policy с раскрытием обработки данных.

## Фазы разработки

**Фаза 0 — Фундамент.** Скаффолдинг, стек, схема БД с миграциями
(`applications`, `documents`, `checklist_items`, `form_templates`), a11y-
конвенции с первого дня.

**Фаза 1 — Чек-лист + хранилище.** Создание заявки, разбивка текста на
пункты, загрузка файлов, шифрование на диске. Рабочий продукт без
автозаполнения.

**Фаза 2 — Финальный PDF-пакет.** Сборка загруженных файлов в один PDF
(`pdf-lib`), автогенерация реестра, детектор некачественных фото при
загрузке.

**Фаза 3 — Каталог форм и docx-парсер.** Первый кейс — сербская форма
(уже разобрана). Оффлайн-утилита разбора docx → JSON-шаблон. Runtime-
сопоставление по fingerprint, заполнение по позиции. Обязательное
подтверждение полей пользователем. Тесты на реальных файлах-фикстурах.

**Фаза 4 — Профиль + MRZ-автозаполнение.** Профиль пользователя, сканирование
паспорта, подстановка данных в поля по маппингу из Фазы 3.

**Фаза 5 — PDF AcroForm пайплайн.** Второй парсер форм на `pdf-lib` за общим
интерфейсом с docx-пайплайном (Шенген и другие PDF-формы).

**Фаза 6 — Расширение каталога, монетизация, облако.** Добавление новых форм
по мере проверки формата каждой. Premium-gate на автозаполнение. Облачная
синхронизация с E2E-шифрованием — по необходимости.
