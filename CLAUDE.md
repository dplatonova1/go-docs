# Проект: чек-лист документов + автозаполнение форм для виз/ВНЖ/ПМЖ

## Описание

Мобильное приложение (React Native, bare, TypeScript). Пользователь вставляет
список требуемых документов (скопированный с официального сайта) →
приложение строит чек-лист → пользователь загружает файлы к каждому пункту →
приложение собирает финальный PDF-пакет для печати с реестром. Отдельно:
автозаполнение официальных форм (docx/PDF) данными из уже загруженных
документов (паспорт и т.п.), премиум-фича.

## Фазы разработки

**Фаза 0 — Фундамент.** Скаффолдинг, стек, схема БД с миграциями
(`applications`, `documents`, `checklist_items`, `form_templates`), a11y-
конвенции с первого дня.

**Фаза 1 — Чек-лист + хранилище.** Создание заявки, разбивка текста на
пункты, загрузка файлов, шифрование на диске. Рабочий продукт без
автозаполнения.

**Фаза 2 — Финальный PDF-пакет.** Сборка загруженных файлов в один PDF
(`@cantoo/pdf-lib`), автогенерация реестра, детектор некачественных фото
при загрузке.

**Фаза 3 — Каталог форм и docx-парсер.** Первый кейс — сербская форма
(уже разобрана). Оффлайн-утилита разбора docx → JSON-шаблон. Runtime-
сопоставление по fingerprint, заполнение по позиции. Обязательное
подтверждение полей пользователем. Тесты на реальных файлах-фикстурах.

**Фаза 4 — Профиль + MRZ-автозаполнение.** Профиль пользователя, сканирование
паспорта, подстановка данных в поля по маппингу из Фазы 3.

**Фаза 5 — PDF AcroForm пайплайн.** Второй парсер форм на `@cantoo/pdf-lib`
за общим интерфейсом с docx-пайплайном (Шенген и другие PDF-формы).

**Фаза 6 — Расширение каталога, монетизация, облако.** Добавление новых форм
по мере проверки формата каждой. Premium-gate на автозаполнение — через
платформенный биллинг (Google Play Billing / Apple IAP), без своего
бэкенда и аккаунта пользователя (см.
[ADR-0006](docs/adr/0006-platform-billing-for-premium.md)). Облачная
синхронизация с E2E-шифрованием — по необходимости, и не раньше публикации
privacy policy ([ADR-0007](docs/adr/0007-privacy-policy-gate-for-cloud-sync.md)).

- *Идея (не решено, требует проработки):* бот-уведомление для
  разработчика на случай, если ведомство поменяло форму (см.
  [ADR-0003](docs/adr/0003-form-catalog-positional-mapping.md) — сейчас
  такое изменение обнаруживается только постфактум, по несовпадению
  fingerprint у пользователя). Периодически проверяет страницы
  ведомств/ссылки на файлы форм и шлёт уведомление (например, в Telegram)
  при изменении. Это отдельный сервис на стороне разработчика, не часть
  приложения — как и оффлайн-утилита разбора форм, он не должен нарушать
  принцип "никакой сети в рантайме у пользователя" (ADR-0002, ADR-0004).
