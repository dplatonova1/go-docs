# src/navigation

Навигация приложения: навигаторы, типы маршрутов и параметров, deep links.

## Библиотека пока не подключена — осознанно

В Фазе 1 у приложения одна активная заявка и два рабочих корневых
состояния: «заявки нет» → экран создания, «заявка есть» → её чек-лист.
Переход между ними — смена состояния, а не стек экранов: возвращаться с
чек-листа на создание заявки нельзя и не нужно. Эту развилку держит
[`RootNavigator`](./RootNavigator/RootNavigator.tsx) — вместе с загрузкой
и ошибкой хранилища.

Библиотека ставится, когда появится первый экран, на который переходят
и с которого возвращаются (например, пункт чек-листа с прикреплением
файлов). Ориентир — React Navigation: Expo Router неприменим, проект не
на Expo ([ADR-0001](../../docs/adr/0001-bare-react-native-new-architecture.md)).
Выбор оформляется ADR, новые нативные зависимости — с проверкой
разрешений ([ADR-0009](../../docs/adr/0009-minimal-android-permissions.md)).

Списка заявок и переключения между ними в Фазе 1 нет — это не пробел
навигации, а граница фазы.

## Конвенции

- **Параметры маршрутов типизированы** (`RootStackParamList` и т. п.) —
  никаких `any` в `navigate`.
- **Аппаратная кнопка «назад» на Android обрабатывается явно** на экранах
  с несохранённым состоянием: заполнение формы, съёмка MRZ, сборка пакета.
  Уход с экрана не должен молча терять введённое. Пример —
  `CreateApplicationScreen`: экран корневой, «назад» закрывает
  приложение, поэтому при непустом черновике сначала подтверждение.
- **Deep links** — только внутренние. Внешних ссылок, открывающих
  приложение с данными, быть не должно.
