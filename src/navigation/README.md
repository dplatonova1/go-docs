# src/navigation

Навигация приложения: навигаторы, типы маршрутов и параметров, deep links.

## Структура

Стек один, `native-stack`
([ADR-0014](../../docs/adr/0014-react-navigation-native-stack.md)):

```
RootStack
├── ApplicationList          — список заявок, корень
├── Checklist                — { applicationId }
├── CreateApplication
├── RenameApplication        — { applicationId }, модально
├── DocumentLibrary          — библиотека документов
├── PickDocumentFromLibrary  — { itemId }, выбор файла для пункта
└── Settings                 — настройки: язык интерфейса
```

При запуске [`useBootstrap`](./RootNavigator/useBootstrap.ts) применяет
сохранённый язык ([ADR-0021](../../docs/adr/0021-runtime-localization.md)
— первым шагом, чтобы сообщение о недоступной базе вышло на выбранном
языке), применяет миграции, читает последнюю открытую заявку и собирает
стартовый стек
([`initialNavigationState`](./RootNavigator/initialNavigationState.ts)):
список, а поверх него — чек-лист последней открытой заявки, а если заявок
нет вообще — экран создания
([ADR-0015](../../docs/adr/0015-multiple-applications-last-opened.md)).
Приложение открывается сразу в работе, но «назад» ведёт в список, а не
закрывает приложение.

## Маршрутные обёртки

[`routes/`](./routes) — тонкий слой между навигацией и экранами. Экраны
из `src/features` навигацию не импортируют: они принимают данные и
колбэки пропсами и проверяются тестами без навигационного контекста.
Обёртка берёт на себя то, что знает только навигация:

- [`ApplicationGate`](./routes/ApplicationGate.tsx) — общая для
  маршрутов заявки загрузка по `applicationId`: индикатор, ошибка чтения
  и случай «заявка удалена» (восстановленный маршрут может указывать на
  удалённую заявку). Экран получает уже загруженную заявку;
- `ChecklistRoute` — поверх гейта ставит название в шапку и отмечает
  заявку открытой;
- `RenameApplicationRoute` — переименование модальным экраном поверх
  списка;
- `CreateApplicationRoute` — подтверждение ухода с непустого черновика
  через `usePreventRemove` (перехватывает кнопку в шапке, жест и
  аппаратную кнопку разом) и переход на созданную заявку;
- `ApplicationListRoute` — переходы из списка; перечитывание списка при
  возврате фокуса;
- `SettingsRoute` — склейка без своей логики: из настроек никуда не
  уходят, только назад кнопкой в шапке.

Заголовки экранов в шапке берутся из словаря
([`i18n`](../i18n/README.md)), поэтому `RootNavigator` вызывает
`useTranslation()` — при смене языка шапки меняются вместе с экранами.

Поэтому у обёрток нет папки на компонент со `styles.ts` и `constants.ts`
— это склейка, а не элементы интерфейса.

## Конвенции

- **Параметры маршрутов типизированы** (`RootStackParamList` в
  [`RootNavigator/types.ts`](./RootNavigator/types.ts)) — никаких `any` в
  `navigate`. Тот же файл подключает типы к `useNavigation()` через
  `ReactNavigation.RootParamList`.
- **В параметрах — только идентификаторы.** Состояние навигации переживает
  выгрузку процесса, поэтому обязано быть сериализуемым, а объект заявки к
  моменту восстановления мог устареть или исчезнуть.
- **Заголовок экрана — в шапке навигации**, своих заголовков экраны не
  рисуют: два подряд скринридер прочитает как два. Заголовок чек-листа —
  название заявки, его ставит `ChecklistRoute` после загрузки.
- **Уход с экрана с несохранённым вводом подтверждается** —
  `usePreventRemove` в маршрутной обёртке, а не `BackHandler` на экране:
  уйти можно кнопкой, жестом и аппаратной кнопкой.
- **Deep links** — только внутренние. Внешних ссылок, открывающих
  приложение с данными, быть не должно, поэтому `linking` у
  `NavigationContainer` не настроен.
