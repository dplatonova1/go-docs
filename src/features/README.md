# src/features

Фичи по вертикалям, каждая — своей папкой (UI + логика + типы).

Компоненты фичи устроены так же, как общие: папка на компонент с
`types.ts`, `styles.ts`, `constants.ts` и `index.ts` — см.
[`../components/README.md`](../components/README.md#структура-компонента).

Ориентир по фазам из `CLAUDE.md`:

- `checklist` — список заявок, создание заявки, разбивка вставленного
  текста на пункты (простая эвристика, без ML/NLP), загрузка файлов
  (Фаза 1). Здесь же `repository.ts` — единственный слой запросов к БД,
  включая запросы документов.
- `library` — библиотека документов: все загруженные файлы, превью,
  прикрепление к пункту без повторной загрузки, удаление файла с
  устройства ([ADR-0017](../../docs/adr/0017-document-library-screen.md)).
  Запросы берёт из `checklist/repository.ts`: два слоя доступа к одним и
  тем же таблицам были бы хуже, чем импорт через границу фичи.
- `package` — сборка финального PDF-пакета с реестром, сжатие снимков,
  детектор некачественных фото, отправка через share sheet (Фаза 2, см.
  [ADR-0019](../../docs/adr/0019-pdf-package-assembly.md)). Запросы
  берёт из `checklist/repository.ts`, как и `library`.
- `settings` — настройки приложения. Пока один раздел, язык интерфейса
  ([ADR-0021](../../docs/adr/0021-runtime-localization.md)); дальше сюда
  придут премиум-статус (Фаза 6) и профиль (Фаза 4). Сами словари — не
  фича, а общий слой [`../i18n`](../i18n/README.md).
- `forms` — каталог форм, docx-парсер (legacy form fields), сопоставление
  по структурному fingerprint, заполнение по позиции + подписи перед
  полем. Рантайм строго детерминированный и офлайн: никакого AI и сети
  (Фаза 3). Позже — PDF AcroForm пайплайн за тем же интерфейсом (Фаза 5).
- `profile` — профиль пользователя и MRZ-сканирование паспорта с
  обязательным ручным подтверждением каждого автозаполненного поля
  (Фаза 4).
