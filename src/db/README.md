# src/db

Локальная БД на `@op-engineering/op-sqlite` и миграции.

Единственная точка входа — [`client.ts`](./client.ts). Остальной код не
должен импортировать `@op-engineering/op-sqlite` напрямую.

Таблицы (Фаза 0): `applications`, `documents`, `checklist_items`,
`form_templates`.

## Правила

- Схема меняется только через нумерованные миграции в массиве
  `MIGRATIONS` в `client.ts`, без «ручных» ALTER в рантайме.
- Уже применённая миграция никогда не редактируется — на устройствах, где
  она отработала, правка не появится. Вместо этого заводится следующая.
- Запросы только параметризованные (`execute(sql, params)`), без склейки
  значений в строку SQL.
- Здесь хранятся только метаданные. Сами файлы документов лежат
  зашифрованными на диске — см. [`../storage`](../storage).

## База зашифрована

Вся БД шифруется SQLCipher тем же ключом, что и файлы документов
([ADR-0002](../../docs/adr/0002-local-first-storage.md)). Перечень заявок
и документов сам по себе чувствителен, поэтому не хранится открытым
текстом даже внутри песочницы приложения.

Из этого следуют две вещи:

1. **SQLCipher включается на этапе сборки** — ключ `op-sqlite.sqlcipher`
   в корневом `package.json`. После его изменения нужна пересборка
   нативной части, иначе настройка не подействует. `client.ts` проверяет
   это в рантайме через `isSQLCipher()` и отказывается открывать базу,
   если нативная часть собрана без SQLCipher, — чтобы не работать без
   шифрования, считая, что оно есть.
2. **`getDb()` асинхронный** — перед открытием базы нужно получить ключ
   из Keychain. При потере ключа оттуда придёт `StorageError` с кодом
   `encryption-key-lost`, и это означает недоступность всех данных,
   включая перечень документов.
