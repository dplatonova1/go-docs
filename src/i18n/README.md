# src/i18n

Переводы интерфейса: русский и английский. Почему свой слой, а не
`i18next` — [ADR-0021](../../docs/adr/0021-runtime-localization.md).

## Модули

| Файл                                       | Назначение                                                       |
| ------------------------------------------ | ---------------------------------------------------------------- |
| [`locales/ru.ts`](./locales/ru.ts)         | Русский словарь — **источник правды по набору ключей**           |
| [`locales/en.ts`](./locales/en.ts)         | Английский словарь, типизирован как `Messages`                   |
| [`types.ts`](./types.ts)                   | `Locale` и `Messages = typeof ru`                                |
| [`store.ts`](./store.ts)                   | Текущий язык: `getLocale`, `setLocale`, `translations`, подписка |
| [`useTranslation.ts`](./useTranslation.ts) | Хук для компонентов, подписан на стор                            |
| [`systemLocale.ts`](./systemLocale.ts)     | Язык устройства — значение по умолчанию                          |
| [`persistence.ts`](./persistence.ts)       | Чтение и запись выбора языка на диск                             |
| [`constants.ts`](./constants.ts)           | `MESSAGES`, `LOCALES`, `LOCALE_NAMES`, фолбэк                    |

## Как брать текст

**В компоненте — хуком:**

```tsx
const t = useTranslation();
// ...
<Summary>{t.checklist.summary(total)}</Summary>
<Button label={t.common.retry} accessibilityLabel={t.checklist.retryA11y} />
```

**В чистом модуле — функцией, в момент, когда строка нужна:**

```ts
import { translations } from '../../i18n';

export function describeError(error: unknown): string {
  const messages = translations().errors;
  // ...
}
```

Словарь, снятый на верхнем уровне модуля, застынет на языке, который был
при загрузке, и останется таким до перезапуска. То же касается колбэков,
живущих дольше рендера: `Alert` внутри `usePreventRemove` берёт словарь
внутри себя, а не замыканием.

**Хук, а не пропсы, у мемоизированных строк списков.** `ChecklistItemRow`,
`ApplicationRow`, `DocumentRow` и `DraftItemRow` под `memo`: с прежними
пропсами они не перерисовались бы при смене языка. Подписку на язык
каждая держит свою — поэтому текст приходит к ним хуком.

## Как добавить строку

1. Добавить ключ в [`locales/ru.ts`](./locales/ru.ts).
2. `npx tsc --noEmit` — он потребует того же ключа в `en.ts`.
3. Перевести в [`locales/en.ts`](./locales/en.ts).

Строка с подстановкой — функция: `(count: number) => \`Пунктов: ${count}\``.
Аргументы тогда проверяет tsc, а порядок слов каждый язык выбирает свой.

## Правила формулировок

- **Числа — в скобках или после двоеточия, без склонения**: «пунктов: 7»,
  «снимки (1)». Так текст остаётся верным при любом количестве, и правила
  плюрализации не нужны — их в проекте нет и добавить нечем (ADR-0021).
- **`accessibilityLabel` называет действие целиком**, а не повторяет
  надпись: «Открепить» в списке из нескольких файлов ничего не сообщает,
  «Открепить файл X от пункта 3» — сообщает.
- **Названия языков не переводятся** («Русский», «English»): человек,
  которому приложение досталось на незнакомом языке, ищет в списке
  знакомое слово. Они живут в `LOCALE_NAMES`, а не в словарях.

## Что НЕ переводится

**Сообщения внутри `Error` и `StorageError`.** Они написаны для
разработчика и пользователю не показываются: экран получает текст через
`describeError()` ([`features/checklist/errorMessages.ts`](../features/checklist/errorMessages.ts)),
который выбирает перевод по коду ошибки. Поэтому в `repository.ts`,
`db/client.ts`, `storage/*` русские строки в `throw` — это норма, а не
пропущенный перевод.

Новый код ошибки добавляется в `StorageErrorCode` или
`AttachmentErrorCode` — и tsc сразу потребует сообщение для него в обоих
словарях: наборы закрыты через `satisfies Record<…>`.

## Что переводится, хотя не выглядит интерфейсом

- **Титульная страница-реестр внутри собранного PDF**
  ([`features/package/registryPage.ts`](../features/package/registryPage.ts)):
  пакет распечатывают и несут в ведомство.
- **Имя готового файла** (`Пакет — ВНЖ Сербия.pdf`) — его видно в share
  sheet. Очистка имени от опасных символов остаётся в
  [`storage/exportFile.ts`](../storage/exportFile.ts) и применяется до
  подстановки в шаблон.
- **Названия месяцев** ([`features/library/formatAddedDate.ts`](../features/library/formatAddedDate.ts)):
  свои, не из `Intl` — полнота ICU в Hermes зависит от сборки.

## Выбор языка и его хранение

Порядок при запуске: язык системы (значение по умолчанию при загрузке
[`store.ts`](./store.ts)) → сохранённый выбор из файла настроек
(`loadStoredLocale()` первым шагом
[`useBootstrap`](../navigation/RootNavigator/useBootstrap.ts)).

Выбор лежит незашифрованным в `settings.json` в приватной песочнице
([`storage/settings.ts`](../storage/settings.ts)). Так он читается до
открытия базы и до обращения к Keychain — и сообщение «ключ шифрования
потерян» выходит на выбранном языке.

**`index.ts` не экспортирует `changeLocale` и `loadStoredLocale`
намеренно.** [`persistence.ts`](./persistence.ts) тянет за собой
нативную файловую систему, а словарь нужен чистым модулям; через барьер
они получали бы `react-native-fs` вместе с текстами, и каждый тест на
формулировку начинался бы с его мока. Два места, которым запись нужна
по-настоящему — запуск приложения и экран настроек, — импортируют
`i18n/persistence` явно.

## Тесты

- [`__tests__/messages.test.ts`](./__tests__/messages.test.ts) — словари
  сходятся: одинаковые ключи, одинаковая форма значений, одинаковое число
  аргументов у функций, нет пустых строк, двенадцать месяцев. Проход идёт
  по всем языкам из `MESSAGES`, поэтому третий язык проверится сам.
- [`__tests__/store.test.ts`](./__tests__/store.test.ts) — переключение и
  подписка.
- [`__tests__/systemLocale.test.ts`](./__tests__/systemLocale.test.ts) —
  разбор языкового тега, включая мусор.
- [`__tests__/persistence.test.ts`](./__tests__/persistence.test.ts) —
  сохранённый выбор, мусор в файле, неудачная запись.

Язык всех тестов проекта — русский, его задаёт
[`test-utils/setupLocale.ts`](../test-utils/setupLocale.ts): иначе его
выбирал бы фолбэк `detectSystemLocale()`, а тесты проверяют формулировки
дословно. Тест, которому нужен другой язык, вызывает `setLocale` сам.
